# 에니어그램 웹사이트 — UX 라이팅 가이드

## 1. 이 문서의 용도와 우선순위

- 화면에 보이는 모든 글(메뉴, 제목, 킥커, 설명문, 버튼, 입력칸, 안내·오류 문구, 공유 문구, 검색 결과)을 쓰거나 고칠 때 이 문서를 기준으로 삼는다.
- 핸드북 본문(`content/handbook-type-store.js`)과 정식 검사 135문항(책 원문)은 콘텐츠이므로 이 문서로 고쳐 쓰지 않는다. 다만 새로 쓰는 요약·안내·버튼은 이 문서를 따른다.
- 우선순위: `CLAUDE.md` > `docs/UI_UX_Harness_Engineering_Guide.md` §6A–6E > 이 문서. 충돌하면 위 순서로 해결한다. 특히 §6D "기존 콘텐츠를 줄이거나 삭제해서 가독성을 해결하지 않는다"와 `CLAUDE.md` 7번(문구·메뉴명은 요청 없이 바꾸지 않는다)이 이 문서보다 앞선다. 이 문서의 부록 A는 "고칠 후보 목록"이지 자동 적용 지시가 아니다.
- 서비스의 목적은 `docs/기능_운영_요구사항.md` §1.1대로 "유형 판정보다 자기관찰 → 비교 → 기록 → 패턴 발견"이다. 글도 같은 방향을 향한다.

## 2. 톤앤매너

한 줄: **옆에서 같이 들여다보는 사람의 말투 — 다정하지만 단정하지 않고, 쉬운 말로, 조용히 확신한다.**

| 성격 | 뜻 | 이렇게 씀 (실제 문구) | 이렇게 안 씀 |
|---|---|---|---|
| 다정하지만 단정하지 않는다 | 결론을 대신 내리지 않고 가능성으로 말한다 | "선미는 3번 성취자에 가까워요" (공유 페이지, `js/00-app-core.js:2113`) | "당신은 3번 유형의 성격을 가지고 있는 것 같다." (`js/00-app-core.js:62`) |
| 관찰을 돕는다 | 답을 주기보다 볼 곳을 알려준다 | "해석보다 실제로 있었던 일을 적어보세요. 언제, 누구와, 어떤 상황이었는지." (`js/02-myspace-feature-script.js:242`) | "당신의 문제는 갈등 회피입니다." |
| 쉬운 말 | 용어보다 일상어, 영어보다 한글 | "힘들 때 먼저 커지는 것" (공유 비교, 중심을 풀어 쓴 말) | "MY ENNEAGRAM", "COMPARE · HORNEVIAN" (`index.html:5996`, `:5570`) |
| 사용자를 판단하지 않는다 | 옳고 그름, 좋고 나쁨을 말하지 않는다 | "상대의 방식이 나와 다를 뿐, 틀린 게 아니에요." (`js/00-app-core.js` 공유 비교) | "불건강한 3번은 거짓말을 합니다." |
| 조용한 확신 | 느낌표·과장 없이 필요한 말만 한다 | "링크를 복사했어요." (`js/00-app-core.js:2201`) | "복사 완료!! 이제 친구에게 공유해보세요!" |

## 3. 말투 규칙

| 항목 | 규칙 | 예 (이 사이트) |
|---|---|---|
| 기본 문체 | 설명문·안내·알림은 **해요체**. 한 화면에 합니다체와 해요체를 섞지 않는다. 핸드북 본문처럼 이미 합니다체로 통일된 긴 콘텐츠는 그 안에서만 유지한다. | 좋음: "여러 개 골라도 괜찮아요." (`js/02:243`) / 섞임: "…가장 자주 느꼈어요. … 단서가 반복되었습니다." (`js/02:204-205`) |
| 제목 | 페이지·섹션 제목은 **명사형** 또는 짧은 질문. "~합니다"로 끝나는 제목은 쓰지 않는다. | 좋음: "세 중심", "요즘 나는 어떤가요?" / 피함: "행동을 봅니다" (`index.html:4894`) |
| 마침표 | 제목·킥커·버튼·칩·라벨에는 없음. 설명문·알림·오류에는 있음. 한 줄짜리 설명(카드 부제)도 문장이면 찍는다. | "다이어리에 기록을 남기면 여기에 모여요." (○) / 제목 "…알아차리는 것입니다." (`index.html:324`, ×) |
| 사용자 지칭 | 사용자는 **"나" / "내"**. "당신", "회원님", "사용자님"은 쓰지 않는다. 시스템이 사용자에게 말할 때는 주어를 생략한다. | "내 결과 보기", "나의 유형 찾기" (○) / "당신은 아마 3번 유형이 아닐 것이다." (`js/00:50`, ×) |
| 사이트 지칭 | "이 사이트", "여기". "저희", "본 서비스"는 쓰지 않는다. | "이 사이트에서는 이렇게 이해해요" (`index.html:4891`) |
| 느낌표 | 쓰지 않는다. 인용된 대표 말투도 UI 안에서는 쉼표나 마침표로 바꾼다. | "재밌겠다! 일단 가보자" (`js/00:1831`) → "재밌겠다, 일단 가보자" |
| 줄임표 | "…", "..."를 쓰지 않는다. 로딩은 "불러오는 중"으로 끝낸다. 예외: 검색 결과 발췌문의 기계적 잘림 표시(`js/06:153`)는 허용. | "불러오는 중…" (`js/00:2144`) → "불러오는 중" |
| 영어 킥커 | 영어 대문자 킥커(MY DIARY, ENNEAGRAM TYPE, COMPARE · CORE 등)는 **새로 만들지 않는다.** 기존 것은 한글 짧은 라벨로 바꾸거나, 바로 아래 제목과 뜻이 겹치면 킥커 자체를 뺀다. 예외: 브랜드 표기 "Enneagram" 로고 1곳(`index.html:72`). | "MY CHANGE" + h2 "나의 변화" (`index.html:6009-6010`) → 킥커 삭제 / "Start here" → "처음이라면" |
| 숫자 | 유형은 "1번", "3번 성취자" (숫자 + 번 + 이름, 사이 공백 1칸). 개수는 아라비아 숫자 + 단위 붙여 씀: "30일", "15문항", "3개". 진행은 "n / 12" (슬래시 양옆 공백). 유형 수는 "9가지 유형"으로 통일("9유형", "9장", "9개 유형"은 쓰지 않는다. 버튼 "9개 모두 선택"처럼 선택 개수를 셀 때만 "개"). | "총 135문항 · 유형별 15문항" (`index.html:537`), "n / 12" (다이어리 진행) |
| 기호 | 구분은 가운뎃점 "·"(양옆 공백). 링크·이동 버튼 끝은 "›", 뒤로는 "‹" (기호와 글자 사이 공백 1칸). "→", "->", ">", "←"는 문구에 쓰지 않는다. "vs"는 유형 비교 제목에서만 허용("1번 vs 3번"). "※", "①②③"은 쓰지 않는다. | "다이어리 쓰기 ›" (○, `index.html:6029`) / "다음 주제 >" (`index.html:5989`, ×) |
| 이모지·장식 문자 | 쓰지 않는다. 체크 표시가 필요하면 아이콘(SVG)으로 처리한다. | "✓" (`index.html:~400` 간편 검사 선택 표시)는 아이콘으로 |
| 괄호 | 보조 설명은 괄호보다 가운뎃점이나 다음 문장으로. 입력칸 옆 "(선택)"은 허용. | "보내는 사람 이름 (선택)" (○) / "해보니 어땠나요? (한 줄)" (`js/02:532`, ×) |

## 4. 에니어그램 특수 규칙

### 4.1 유형은 단정하지 않는다

- 결과·요약·비교 어디서든 유형은 "가까워요", "로 보여요", "일 수 있어요", "후보"로 말한다. "입니다", "이다", "확정", "판정", "진단"으로 유형을 말하지 않는다.
- 점수는 "N점"까지만 사실로 말하고, 해석은 가능성으로 말한다. `docs/기능_운영_요구사항.md` §10.2대로 "당신은 83% 3번입니다" 식 표현은 금지.
- 유형 이름 뒤에 사람을 붙이지 않는다: "3번인 사람들은" (×) → "3번에 가까울수록", "3번 패턴이 강할 때" (○).

| 쓰지 않는 표현 | 대신 쓰는 표현 |
|---|---|
| 당신은 N번입니다 / N번이다 / N번으로 확인되었습니다 | N번에 가까워요 / N번 쪽으로 보여요 |
| 진단, 판정, 검진, 결과 확정 | 검사, 결과, 후보, 가까운 유형 |
| 궁합, 잘 맞는 유형, 안 맞는 유형, 최고의 짝, 상극 | 다르게 반응하는 지점, 오해가 생기기 쉬운 지점 |
| 우열: 좋은 유형, 나쁜 유형, 높은 유형, 성숙한 유형 | (쓰지 않음) 유형은 좋고 나쁨이 없어요 |
| 건강한 N번 / 불건강한 N번 | 건강할 때 / 스트레스일 때 (핸드북 요약 `js/00:` "건강할 때", "스트레스일 때"와 동일) |
| 통합 방향 / 비통합 방향 (UI 라벨로) | 더 건강해질 때 가는 방향 / 스트레스일 때 가는 방향. 개념 페이지 본문 안에서는 원어 유지 가능 |
| 병리, 장애, 신경증, 우울증, 불안장애, 치료 | 힘든 상태, 오래 이어지는 불편함, 전문가 (임상 용어는 쓰지 않는다) |
| 타인 유형 판정: "그 사람은 8번이에요" | "상대가 8번에 가깝다면" (받은 카드도 "N번에 가까워요"로만) |

### 4.2 "정답 아님" 안내 — 표준 문구 1개

결과·요약·집계 화면에는 아래 문장 하나를 그대로 쓴다. 변형을 만들지 않는다.

> **이 결과는 정답이 아니라 나를 살펴보는 단서예요. 행동보다 ‘왜 그렇게 했는지’가 나와 맞는지 확인해보세요.**

현재 사이트에서 같은 뜻을 여섯 가지로 쓰고 있다(`index.html:4855` "※ 점수는 자기 탐색을 위한 참고 자료입니다…", `js/02:299` "이 결과는 유형 판정이 아니라…", `js/00:2114` "유형은 사람을 단정하는 이름표가 아니라…" 등). 화면 성격상 짧게 써야 하면 앞 문장만 쓴다.

### 4.3 힘든 상태의 사용자를 위한 안전 문구 — 표준

핸드북 "요즘 힘들어요" 분기, 다이어리 감정 선택, 나의 변화처럼 사용자가 힘든 상태를 고를 수 있는 곳에는 아래 문장을 쓴다. 겁주지 않고, 판단하지 않고, 다음 행동 하나만 건넨다.

> **여기 있는 내용은 성격 패턴을 이해하기 위한 것이지, 마음 상태를 진단하는 것이 아니에요. 힘든 마음이 여러 날 이어진다면 믿을 수 있는 사람이나 전문가에게 이야기해보세요.**

- "위험", "경고", "심각" 같은 말로 제목을 달지 않는다. 현재 "이런 신호가 보이면 잠깐 멈춰 주세요" (`js/00:496`)처럼 행동을 권하는 제목이 맞다.
- 사용자가 적은 기록을 평가하는 문장을 만들지 않는다("부정적인 감정이 많아요" ×). 개수만 말한다("서운함을 5번 골랐어요" ○).

## 5. 화면 요소별 패턴

각 항목: 규칙 / 좋은 예 2개(사이트에 있거나 규칙에 맞게 고친 것) / 나쁜 예 1개(현재 사이트).

### 5.1 페이지 제목 (h1)

- 규칙: 메뉴명과 같은 말을 쓴다. 20자 이내, 명사형 또는 질문 하나, 마침표 없음. 한 페이지에 h1은 하나.
- 좋음: "다이어리" (`index.html:6052`) / "어떤 방식으로 확인해볼까요?" (`index.html:344`)
- 나쁨: "나를 알아가는 공간" (`index.html:5997`, 메뉴명은 "나의 공간") → "나의 공간"

### 5.2 킥커 (제목 위 작은 라벨)

- 규칙: 한글 2~6자, 마침표·영어 없음. 아래 제목과 뜻이 같으면 킥커를 두지 않는다. 단계 표시는 "1단계", 번호 표시는 "01".
- 좋음: "공유하기" (`js/00:2082`) / "받은 카드" (`js/00:2112`)
- 나쁨: "FULL CHECK · STEP 1" (`index.html:367`) → "정식 검사 · 1단계"

### 5.3 섹션 제목 (h2·h3)

- 규칙: 명사형 또는 짧은 질문, 20자 이내, 마침표 없음. "~합니다"로 끝내지 않는다. 같은 화면의 형제 제목은 형태를 맞춘다(모두 명사형이거나 모두 질문).
- 좋음: "자주 느낀 감정" (`index.html:6039`) / "무엇이 먼저 커지는가?" (`index.html:272`)
- 나쁨: "행동을 봅니다 / 이유를 묻습니다 / 반복되는 초점을 찾습니다 / 선택의 폭을 넓힙니다" (`index.html:4894-4897`) → "행동 보기 / 이유 묻기 / 반복되는 초점 찾기 / 선택의 폭 넓히기"

### 5.4 설명문

- 규칙: 해요체, 2문장 이내, 60자 이내. 첫 문장은 "이게 무엇인지", 둘째 문장은 "무엇을 하면 되는지". 폭은 UI 가이드 §6A.4(설명문 640px)를 따른다.
- 좋음: "다이어리의 ‘다음엔’이 여기 모여요. 해봤다면 체크하고, 해보니 어땠는지 한 줄 남겨보세요." (`index.html:6070`) / "여러 개 골라도 괜찮아요." (`js/02:243`)
- 나쁨: "각 문항에서 나와 가까운 정도를 1~5점으로 선택하세요. 유형별 총점과 책의 점수 해석을 자동으로 보여줍니다." (`index.html:536`, 하세요/합니다 혼용) → "문항마다 나와 가까운 정도를 1~5점으로 골라요. 유형별 총점과 점수 해석을 바로 보여줘요."

### 5.5 주 버튼 (Primary)

- 규칙: 동사로 끝낸다("~하기", "~보기"). 2~5어절, 8자 이내(목적어가 꼭 필요하면 12자까지). 마침표·기호 없음. 한 화면에 주 버튼은 하나.
- 좋음: "간편 검사하기" (`index.html:~356`) / "나의 유형 찾기" (`index.html:209`)
- 나쁨: "기록 저장" (`js/02:350`) → "저장하기"

### 5.6 보조 버튼 (Secondary·텍스트 버튼)

- 규칙: 주 버튼과 같은 형태이되 더 짧게. 되돌리기·닫기·이동은 명사형 2~4자 허용("이전", "다음", "닫기", "삭제", "전체").
- 좋음: "검사 방식 다시 고르기" (`index.html:365`) / "건너뛰기" (`js/02:349`)
- 나쁨: "추가" (`index.html:6075`, 입력칸 옆 주 동작인데 2자) → "추가하기"

### 5.7 텍스트 링크

- 규칙: "명사 + 보기 ›" 형태. 기호는 "›"만, 글자와 기호 사이 공백 1칸. "더 보기"만 단독으로 쓰지 않고 무엇을 더 보는지 적는다.
- 좋음: "다이어리 쓰기 ›" (`index.html:6029`) / "에니어그램 이해 전체 보기" (`index.html:230`, "›"를 붙이면 더 좋다)
- 나쁨: "다음 주제 >" (`index.html:5989`) → "다음 주제 ›"

### 5.8 칩·필터

- 규칙: 명사 1~4자, 마침표 없음. 상태 칩은 사용자 말로("해볼 것 / 해봤어요"), 분류 칩은 명사로("일상 / 가족"). 기본 선택은 "전체".
- 좋음: "해볼 것 / 해봤어요 / 전체" (`js/02:519`) / "최근 30일 / 전체" (`index.html:6026`)
- 나쁨: "① 먼저 보는 것" (`index.html:~5419`, 원문자 번호) → "먼저 보는 것"

### 5.9 입력칸 라벨·플레이스홀더

- 규칙: 라벨은 질문 또는 명사("보내는 사람 이름"). 플레이스홀더는 **실제로 입력할 법한 값** 하나를 "예: " 뒤에 쓴다. 플레이스홀더에 질문·지시·형식 설명을 넣지 않는다("예)"가 아니라 "예:").
- 좋음: "예: 선미" (`js/00:2090`) / "예: 회의에서 내 의견이 반려된 날" (`js/02:252`)
- 나쁨: "해보니 어땠나요? (한 줄)" (`js/02:532`) → 라벨 "해보니 어땠나요?", 플레이스홀더 "예: 생각보다 어렵지 않았다"

### 5.10 도움말 (입력칸 아래 힌트)

- 규칙: 1문장, 40자 이내, 해요체. 무엇을 적으면 되는지 또는 무엇이 일어나는지만.
- 좋음: "비워 두면 첫 문장으로 정해요." (`js/02:252`) / "아주 작은 행동 하나면 충분해요." (`js/02:251`)
- 나쁨: "A·B·C와 1·2·3을 모두 고르면 조합에 해당하는 유형을 보여줍니다." (`index.html:508`) → "둘 다 고르면 가까운 유형을 보여줘요."

### 5.11 빈 상태

- 규칙: 굵은 제목 1줄("아직 ~이 없어요") + 다음 행동 1문장. 자책이나 재촉("아직도 안 쓰셨네요") 없음.
- 좋음: "아직 기록이 없어요. / 위에서 오늘의 장면 하나를 적어보세요." (`js/02:428`) / "아직 보여줄 흐름이 없어요. / 다이어리에 기록을 남기면 여기에 모여요." (`js/02:124`)
- 나쁨: "아직 15문항을 모두 완료한 유형이 없습니다." (`index.html:4853`, 다음 행동 없음·합니다체) → "아직 15문항을 모두 답한 유형이 없어요. 위에서 유형 하나를 골라 이어서 답해보세요."

### 5.12 오류

- 규칙: 1문장에 "무슨 일 + 무엇을 하면 되는지". 해요체, "오류", "실패", "잘못"이라는 말보다 상황을 말한다. 코드·기술 용어 없음.
- 좋음: "장면을 한 줄이라도 적어주세요." (`js/02:366`) / "보낼 유형을 하나 골라주세요." (`js/00` 공유 오류)
- 나쁨: "이 브라우저는 압축된 핸드북 데이터를 열 수 없습니다." (`js/00:286`) → "이 브라우저에서는 핸드북을 열 수 없어요. 최신 크롬이나 사파리로 열어보세요."

### 5.13 확인·저장 알림

- 규칙: "~했어요." 1문장. 필요하면 어디서 볼 수 있는지 한 문장 추가. 3초 안에 읽히는 길이.
- 좋음: "링크를 복사했어요." (`js/00:2201`) / "기록을 저장했어요. 아래 ‘나의 기록’에서 볼 수 있어요." (`js/02:374`)
- 나쁨: (해당 없음 — 저장 알림 없이 목록만 갱신되는 성장 실험 추가는 "실험을 추가했어요."를 붙인다)

### 5.14 삭제 확인

- 규칙: 되돌릴 수 없는 삭제는 반드시 확인한다. 형식: "이 [대상]을 삭제할까요? 삭제하면 되돌릴 수 없어요." 버튼은 "삭제하기 / 취소". "정말", "진짜"는 쓰지 않는다.
- 좋음: "입력한 135문항의 응답을 모두 초기화할까요?" (`js/00:249`, 뒤에 "지우면 되돌릴 수 없어요."를 붙이면 완성) / "이 기록을 삭제할까요? 삭제하면 되돌릴 수 없어요."
- 나쁨: 다이어리 기록 "삭제" (`js/02:458`, 확인 없이 바로 삭제)

### 5.15 진행 표시

- 규칙: "n / 12" (현재 / 전체, 슬래시 양옆 공백). 단계 이름을 함께 쓸 때는 "3 / 12 · 나의 반응". 퍼센트는 쓰지 않는다.
- 좋음: "n / 12" (다이어리 진행 막대) / "성장 실험 3 / 5" (나의 변화)
- 나쁨: "0 / 0" (`index.html:6034`, 실험이 없을 때) → 빈 상태 문구로 대체("아직 성장 실험이 없어요")

### 5.16 공유 문구

- 규칙: 받는 사람이 첫 문장만 보고 무엇인지 알게. "N번 [이름] 카드" + 무엇을 할 수 있는지 1문장. 궁합·점수·비교 우위 없음.
- 좋음: "3번 성취자 카드를 보냈어요. 나와 비교해보세요." (`js/00:2207`) / "선미는 3번 성취자에 가까워요" (`js/00:2113`)
- 나쁨: (해당 없음 — "우리 궁합은 87%" 같은 문구는 만들지 않는다)

### 5.17 검색 결과 없음

- 규칙: "검색 결과가 없어요." + 다른 검색어 예시 3~5개. 예시어 세트는 사이트 전체에서 하나로 통일한다.
- 좋음: "검색 결과가 없어요." + "다른 단어로 검색해보세요. 예: 불안, 관계, 성장, 핵심 동기" (`js/06:190-192`)
- 나쁨: 예시어가 세 곳에서 다 다름 — 검색창 "유형, 동기, 면접, 분노" (`index.html:52`), 처음 화면 "3번, 면접, 분노, 날개, 호니비언" (`js/06:186`), 없음 화면 "불안, 관계, 성장, 핵심 동기" (`js/06:192`) → 하나로 통일: "예: 3번, 불안, 면접, 날개, 호니비언"

## 부록 B. 유형 이름 표준 적용 위치

### 결정: 1번 **개혁가**, 2번 **조력가** (나머지 7개는 이미 일치)

표준 9개: 1번 개혁가 · 2번 조력가 · 3번 성취자 · 4번 개인주의자 · 5번 탐구자 · 6번 충실가 · 7번 열정가 · 8번 도전자 · 9번 평화주의자

이유:

1. 원본 강의 자료 `에니어그램_PPT목차_강의계획서_최종_유형소개포함.md`가 "1번 개혁가", "2번 조력가"로 일관되게 쓴다(Slide 11·12·13, §7 유형별 상세 소개). 이 사이트의 유형 설명·두려움·욕망 문구는 이 자료에서 왔다.
2. 사이트에서 사용자가 가장 많이 보는 곳이 이미 "개혁가/조력가"다: 핸드북 데이터(`js/00-app-core.js:726` `DATA.types`), 정식 검사 유형 고르기 화면(`index.html:377-378`), 홈 프로필 카드·공유 카드·핸드북 요약(`CHECK_TYPE_NAMES`, `js/00-app-core.js:1341`).
3. "개혁자/조력자"는 세 곳의 오래된 상수(`QUICK_TYPE_NAMES`, `TYPE_LABELS`, `TYPES`)와 정적 마크업 2곳에만 남아 있어 바꾸는 범위가 더 작다.
4. 참고: 두 PDF(`에니어그램분석사_이진원_교안모음.pdf`, `…예상문답.pdf`)는 글꼴에 유니코드 매핑이 없어 텍스트를 추출할 수 없었다(pdftotext 결과가 빈 글자, PDF 렌더링 도구 없음). 교안 5장 "유형별 특징" 페이지에서 유형 이름을 직접 확인하지 못했으므로, 원본 강의 md 파일을 근거로 삼았다.
