# 정보 구조 (메뉴 구조) — 2026-10-07

메뉴를 바꾸거나 새 기능·화면을 넣을 때 이 문서를 먼저 본다. 코드에서는 `js/00-app-core.js`의 `PAGE_TAB`(화면 → 하단 탭) · `TAB_OPEN`(탭 → 첫 화면) · `TOP_BACK`(안쪽 화면 → 뒤로 갈 곳)이 이 문서와 같아야 한다.

## 0. 이 앱이 하는 일

**"이야기하면 분석이 쌓이고, 내 패턴이 보이는 앱."** 축은 셋이다.

| 축 | 탭 | 하는 일 |
|---|---|---|
| 유형 | 유형 탐구 (+ 홈 맨 위 9가지 유형 카드) | 에니어그램과 9가지 유형을 알아 간다. 글은 주제별 줄로, 새로고침할 때마다 섞여서 |
| 기록 | 분석 노트 → 나의 공간 | 오늘 장면을 이야기하고 분석을 받는다 → 쌓인 것을 돌아본다 |
| 관계 | 같이 보기 | 같은 장면 · 같은 질문에서 서로 다른 반응을 나란히 본다. 하기 어려운 말을 연습한다 |

## 1. 원칙: 탭 하나 = 질문 하나

| 하단 탭 (코드 id) | 답하는 질문 | 성격 | 아이콘 선 색 |
|---|---|---|---|
| **홈** (home) | 지금 뭘 하면 좋을까? | 맨 위 9가지 유형 카드(항상) + 각 탭에서 한 조각씩 꺼낸 피드 | — |
| **유형 탐구** (explore) | 에니어그램과 9가지 유형은 어떤 걸까? | **읽기**. 주제별 줄(옆으로 넘김), 새로고침마다 다른 글 | 하늘 (알기) |
| **같이 보기** (community) | 관계 속에서 나는 어떻게 반응할까? | **관계**: 한 장씩 넘기는 오늘의 놀이 덱 | 라벤더 |
| **분석 노트** (state) | 오늘 무슨 일이 있었고, 그래서 뭘 해볼까? | **지금 하는 것**: 보석 상태 → 이야기하기 → 이번 주 해볼 것 → 쌓인 분석 (한 화면) | 살구 (기록) · 민트 (실천) |
| **나의 공간** (myspace) | 나는 어떤 사람이고, 무엇이 쌓였을까? | **쌓인 것**: 내 유형 한 줄 · 숫자 세 칸 · 보석 상태 변화 · 통계 요약 · 찾은 패턴 | 라벤더 (검사·유형) |

- **무게 맞추기:** 한 탭이 너무 무겁거나 비지 않게, '지금 하는 것'은 분석 노트, '쌓인 것'은 나의 공간으로 나눈다. 홈은 각 탭에서 한 조각씩.
- **분석 노트는 칸 나눔 없이 한 화면.** 살펴보기 · 다이어리 · 보석 닦기로 자르면 하나의 과정이 셋으로 갈라져 어색했다 (2026-10-07). 이야기하기 · 행동 고르기 · 나의 기록은 안쪽 화면이다.
- 이름에 '진단'은 쓰지 않는다 (PRD §8, UX 라이팅 가이드). 채팅 기록은 화면에서 '이야기하기'라고 부른다. '상담'은 실제 상담·치료로 오해될 수 있어 쓰지 않는다 (PRD §3 비목표).
- 검사는 탭으로 두지 않는다. 홈의 검사 배너(항상)와 나의 공간 내 유형 줄에서 들어간다. 검사 화면에서는 '홈' 탭이 켜진다.
- 화면 하나의 기본 행동(채운 버튼)은 하나: 분석 노트는 '이야기 시작하기'.
- **탭 첫 화면에는 제목 · 설명을 두지 않는다** (2026-10-07). 하단 탭이 이미 위치를 알려 주므로 바로 내용부터. 제목(h1)은 화면 읽기용(.sr-only)으로만 남긴다. 안쪽 화면(이야기하기 · 보석 닦기)은 제목을 보여준다.

## 3. 새 기능을 넣을 때

1. **기능마다 집은 한 곳.** 다른 화면에는 그 집으로 가는 링크(홈 줄, 버튼)만 둔다.
2. **어느 탭인지는 성격으로 정한다.**
   - 누구에게나 같은 지식·글 → 유형 탐구
   - 다른 사람과 함께 하거나 관계 속 나를 보는 것 → 같이 보기
   - 오늘 이야기하고, 살피고, 해 보는 것 → 분석 노트
   - 나에 대해 쌓인 결과 · 기간별 리포트 · 설정 → 나의 공간
3. **홈은 아무것도 소유하지 않는다** (9가지 유형 카드만 예외: 홈의 얼굴). '오늘 할 만한 것'이면 홈 '오늘'에 한 줄을 더한다 (`renderHomeShelves`). 줄은 4~5개를 넘기지 않는다.
4. **하단 탭은 다섯 개로 고정.** 새 기능은 기존 탭 안의 섹션이나 안쪽 화면으로 들어간다. 칸 나눔 메뉴는 만들지 않는다.
5. **콘텐츠는 주제별 줄로 묶고, 줄 안의 글은 새로고침마다 섞는다.** 카드는 한눈에 들어오는 크기(옆으로 넘기는 줄)로.
6. **같이 보기에 새 놀이를 넣을 때는 덱 카드 종류를 하나 더한다** (js/12 `KINDS` · `makeCard` · `cardHTML` · `ART`). 들어가서 하는 화면을 따로 만들지 않고 카드 한 장 안에서 끝나게.
7. **홈과 나의 공간은 모양을 다르게 한다.** 홈은 '오늘 할 것' 줄 목록(앞으로), 나의 공간은 숫자 · 타임라인 · 리포트(지나온 것). 같은 줄 목록 모양을 두 곳에 쓰지 않는다.
8. **코드에 등록한다.** 새 화면(page-panel)을 만들면 `PAGE_TAB`에 한 줄, 뒤로 갈 곳이 있으면 `TOP_BACK`에 한 줄, 주소(`#…`)를 하나 정한다. `tools/visual-check.py`의 화면 목록에도 넣는다.

## 4. 앞으로 들어올 기능의 자리 (PRD v2 기준)

| 기능 | 자리 |
|---|---|
| 상세 검사 (유료, 현재 상태 구간) | 분석 노트 > 보석 상태 · 나의 공간 (검사 이력) |
| 마음 상태 리포트 · 반복 패턴 알림 | 분석 노트 > 쌓인 분석 |
| 주간 회고 · 상태 타임라인 | 나의 공간 (월의 나 옆) |
| 육아 테마 · AI 피드백 · 사람별 장면 태그 | 분석 노트 > 이야기하기 |
| 기록 검색 · 태그 | 분석 노트 > 나의 기록 |
| 성장 연습 · 체크인 · 리마인드 | 분석 노트 > 이번 주 해볼 것 (오늘 할 것은 홈 '오늘'에 한 줄) |
| 나 사용설명서 · 글쓰기형 커뮤니티 (P2) | 같이 보기 |
| 로그인 · 결제 · 전체 내보내기·삭제 · 동의 | 나의 공간 (설정·데이터 섹션) |
| 전체 검색 | 상단 바 (탭과 별개) |

## 5. 남은 정리

- 숨겨 둔 예전 데스크톱 상단 메뉴(`.top-global-nav`)와 사이드바(`.shell-sidebar`)에 옛 메뉴 체계가 남아 있다. 가이드 Phase 3~4 때 `PAGE_TAB` 기준으로 정리한다.
- '연마 처방전'을 '분석 카드'로 부를지 정한다 (지금은 화면 안내에 두 말이 섞여 있다).
- 같이 보기 카드 섞는 비율(`KINDS`)은 쓰는 걸 보고 조정한다 (지금 나라면? 3 · 맞히기 2 · 둘이서 2 · 닮은 두 유형 · 말 연습 · 물어볼 말 각 1).
